# v0.6 integration candidate

This pass hardens the public API and the relationship between vkmin and sndmin.
It is a tested integration candidate, not a declaration that every release gate
in [the review](v0.6-review.md) has passed.

## One timeline, two owners

Game code owns time, input and simulation. vkmin owns rendering resources and
command submission. sndmin owns audio resources and hands timestamped commands
to its mixer. They share a borrowed journal file, not a combined context.

`demo/valley_path.h` now evaluates the camera and its analytic velocity from
the integer tick. The valley audio adapter advances **every tick** up to the
next requested image. Four screenshots over the two-minute route consequently
contain the same audio performance as 61 screenshots. Rendering fewer frames
no longer omits pad changes, birds, wind updates or listener movement.

The end of the camera route clamps both position and velocity. The demo's
120-second capture ends while environmental voices are still playing; it is
not a seamless audio loop. The standalone score retains its four-second tail.

`examples/sndmin/06_unison.c` is the smaller public-header client. The same C11
source builds with audio alone or with graphics enabled. It samples input,
updates a plain value, schedules a spatial note and changes the image on the
same tick. P pauses gameplay and mutes output, M toggles mute, R stops the
current note and restarts gameplay. Pausing does not freeze the device clock
or seek existing voices. `--script` generates those same input edges for tests;
both real and scripted input are recorded as game packets.

```
make -f Makefile.sndmin sndmin
build/sndmin/06_unison tests/out/sndmin/unison --script
make HEADLESS=1 build/sndmin_unison
build/sndmin_unison tests/out/sndmin/unison-av --script --headless --frames 0,60,100,150,200,260,299 --out-dir tests/out/sndmin
```

Use `tools/test_unison.py` to render and verify the example automatically. Its
three expected audio attacks are at absolute ticks 60, 150 and 260. Every tick
maps to exactly 800 mixer samples. The shared journal reproduces the images and
PCM; replay does not need the example's game logic.

## Defaults, gain and failure

The public A/V example exposed a renderer defect: an unnamed pass skipped
`vkCmdBeginDebugUtilsLabelEXT` but still issued the matching end operation.
Validation rejected the submission. Debug passes now always begin a label,
using `vkmin.pass` when no name is supplied. The same example exercises this
case on both replay paths. Header text also now spells out that
`frame_begin(NULL)` opens no pass and an explicit pass requires `pass_end`.

Creation descriptors retain zero defaults for source compatibility. Setter
gains are literal: zero mutes, one is unity. New code should use
`sndmin_bus_set(ctx, SNDMIN_MUSIC, gain)` after `sndmin_frame`. It returns whether
the request was accepted and persists across frames. Once explicitly set, that
bus overrides the legacy `frame.bus_gain` field. Set one to restore unity.
The old frame field remains readable with its documented zero/default rule;
no native command payload layout changed for this addition.

Resource loaders and `sndmin_play` return zero handles on rejection. Invalid
resource descriptors, missing files and capacity exhaustion are recoverable
when `sndmin_ok(ctx)` remains true. Invalid frame order, failed journal writes,
command allocation/queue failures and failed output writes poison the context:
stop issuing work, report the failed operation and shut it down. Check the
render result as well as resource handles. This supplies a small explicit
failure path without a user callback or an error-message allocation.

The renderer retains its documented fatal contract failures; it is not silently
converted to recoverable errors by the audio changes. Audio setters for unknown
or expired voices remain harmless. For compatibility, older audio code may
queue sample-zero plays before the first frame; new clients call frame first
so the listener and geometry are present before spatial commands.

Song loading now parses into temporary patch descriptions and checks capacity
before creating any resource. A malformed song leaves resource counts and
journal bytes unchanged. Journal IO failure during the commit is terminal;
there is no claim of filesystem transactionality after a failed write.

## Lifetimes and thread boundaries

| Value | Ownership and lifetime |
|---|---|
| `vkmin_ctx *` | Caller shuts it down; rendering calls are ordered on one thread. Global platform/cvar state still limits independent renderer contexts. |
| Graphics handles | Typed generation-tagged numbers; free explicitly after the documented GPU lifetime. Backbuffer/depth handles are borrowed from the context. |
| Texture slot or GPU address | A reference to a live registered texture/buffer, not a resource owner or a scene ID. |
| `sndmin_ctx *` | One game-thread owner. Shutdown stops and joins the device before freeing mixer resources. |
| Sound, stream, patch, song | Context-local typed indices. PCM and patch data are copied; resources become immutable on the first frame and live until shutdown. No individual unload operation is added. |
| Audio voice | Context-local command ID. May finish or be stolen; holding its number does not keep it alive. Do not pass handles between contexts. Index bounds do not establish cross-context identity. |
| Frame geometry/material arrays | Audio copies them during the frame call; temporary caller arrays are valid. |
| Shared journal `FILE *` | Open with `jrnl_open`, lend it to both init descriptors, close after both shutdowns and offline audio rendering. Neither library closes a borrowed stream. |

The wind adapter now uses the shared public scalar math function
`vkmin_sin_cycles`; it no longer includes sndmin's private DSP header. The
scalar polynomial is unchanged, and all existing audio WAV goldens are retained.
Audio still depends only on the shared numeric headers, never the Vulkan SDK.

## Journal compatibility

New audio captures carry a small schema packet: version, 48 kHz rate, 800-sample
tick, channel count, command/patch sizes and byte-order marker. Replay rejects
incompatible metadata rather than silently mixing the wrong layout. Existing
version-1 journals without metadata remain supported and are tested against
their frozen WAVs. Select a matching channel layout before replay.

Video packet timestamps must not decrease. Audio packet timestamps can decrease:
a tracker emits future notes before streamed PCM is appended during rendering.
Enforcing one global monotonically increasing packet time would reject valid
journals. Audio checks each packet's time against its command sample position.

Payloads remain native C layouts for compatible little-endian, IEEE-float
builds. The new metadata is not a general wire-format or asset migration system.
Input-demo build/asset identity and portable payload serialization remain open
review items. Pixel equality across arbitrary GPU drivers is not promised.

## Verification and release limits

The source was frozen in `build/v06-review` before modifying the audio core,
because another task was active in the same checkout. The pre-change baseline
was **107 graphics checks, six failures**. Current/frozen valley comparisons
passed. The failures were Corridor frames 0/120/240/360, overlay and debug 3.
No old graphics or audio golden was replaced by this integration pass.

The two-minute route test runs 7,200 audio ticks under 4-image and 61-image
render schedules and compares the complete WAV, spectrogram and four checkpoint
PNGs. Both Vulkan journal replay paths are included. The public API tests check
256 rejected songs without resource/journal changes; literal persistent bus
mute, restore and stop; both header include orders; and failed-context rejection.
The public A/V probe adds pause, restart, timed note onsets and malformed video
packet order. Audio schema corruption tests cover all seven metadata fields.

Final Windows GCC 16.2.0/lavapipe run: **110 graphics checks, six failures**,
the same six historical Corridor comparisons. All added integration checks,
mandatory analysis, shader validation and the complete audio suite passed.
The concurrent audio task's serial/threaded comparison was included: 7.1 PCM,
synth, Vorbis and acoustics agree through unsigned ring-counter rollover.
The callback audit follows 24 functions and permits only memcpy/memset and
lock-free atomic operations outside the translation unit.

A separate frozen build with LLVM-MinGW Clang 22.1.8 at `-O1` passed AddressSanitizer
and UndefinedBehaviorSanitizer, all six fresh audio examples, old frozen goldens,
11 malformed/incompatible journal rejections, public API tests and the thread
comparison. `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1` was used on Windows;
this is not LeakSanitizer or ThreadSanitizer coverage. No physical device played.
The source copies are `build/v06-review` and `build/v06-sanitize`; final logs
are `build/v06-final.log` and `build/v06-asan.log`.

Open gates: explain the six historical Corridor golden differences, execute
Linux/macOS and leak/race sanitizer CI, measure live A/V latency and sustained hardware
playback, and have a working C developer try the headers and example. No Linux
distribution is installed in this Windows machine's WSL. Headless success does
not establish those results, and this document does not claim a human usability
or listening assessment.
