# Build prompt: `vkmin` v0.3 — the API people would actually want

Paste this to the coding agent. It assumes v0.2 is complete and `make test` passes on both
paths. `CLAUDE.md` still governs. Where this document and v0.1 or v0.2 disagree, this one wins.

---

## The brief

v0.1 proved the plumbing. v0.2 modernised it. v0.3 is about the surface: the header a new
engineer reads, the forty lines they write to get a cube, and the feeling they have while doing
it. The target is a C11 API that an experienced engineer reads once and understands, that a
first-week engineer gets a textured cube out of in under an hour with no documentation beyond
the header, and that Carmack would recognise as built the way he has argued code should be
built.

Nothing here adds a rendering feature. Everything here removes a concept from the user's mind.

## What beloved C APIs have in common

Before designing, study four things and write down what they share: `stb_image.h`,
`sokol_gfx.h`, `raylib.h`, and the Lua C API. The common properties are not accidental.

They drop in with no build-system negotiation. They use one consistent prefix and `verb_noun`
names, so any function can be guessed before it is looked up. They take configuration as a
struct where a zero field always means the sensible default, so that the shortest call is the
common case and every option is discoverable by reading the struct. They never call back into
user code. They allocate nothing the user did not ask for. Their header *is* the documentation.
And they come with numbered examples short enough to read in one sitting, each of which actually
runs.

Every one of those is also a point `CLAUDE.md` makes for a different reason. A struct of options
with zero defaults is explicit state. No callbacks means no hidden control flow. One prefix means
every call site is greppable and the call graph is visible. Those APIs are loved because they
are legible, and legibility is what the regime is for.

## The one idea v0.3 is built around: resources are numbers

Everything a shader needs to know about a resource fits in an integer. A texture is a `uint32`
index into one bindless array bound once per frame. A buffer is a `uint64` device address. Both
travel to the shader in the push-constant block, alongside whatever else the draw needs, in a
struct declared once in `shared.h` and seen identically by C and GLSL.

Consequently, **the API stops having a binding model.** `vkmin_bind` is deleted. There is no
vertex buffer binding, no index buffer binding, no descriptor set binding, no "which texture slot"
question. A draw is:

```c
vkmin_draw(ctx, pipe, &(cube_push){
    .mvp      = mvp,
    .vertices = vkmin_address(ctx, vb),
    .texture  = vkmin_index(ctx, tex),
}, sizeof(cube_push), 36, 1);
```

The vertex shader pulls vertices from the address. The fragment shader samples
`textures[push.texture]`. The index buffer, if there is one, is also an address in the push
block and the draw is non-indexed from Vulkan's point of view, with the shader doing the index
fetch — or it is passed as a separate optional handle for a true indexed draw; pick one and do not
offer both. This needs descriptor indexing and buffer device address, both core in 1.2 and both
exposed by lavapipe, so it works on the legacy and modern paths alike.

This is the single biggest legibility win available. The entire mental category "how do I get
this resource to the shader" collapses into "put its number in the struct". It also happens to
be the fast path on real hardware and the shape the v0.1 engine was already going to need.

## The header

`vkmin.h` is the documentation. Budget: 300 lines including comments. Rules:

**Typed handles.** `typedef struct { uint32_t id; } vkmin_image;` and likewise for buffers and
pipelines. Not bare integers — the compiler should refuse an image where a buffer belongs. Zero
is invalid for every type. `vkmin_valid(h)` works on any of them.

**Descriptor structs, zero means default.** Every `make_*` takes a pointer to a desc struct
designed so that leaving a field at zero gives the sensible choice. `vkmin_make_image` with only
`.width`, `.height` and `.pixels` set produces an RGBA8 sampled texture with a linear-repeat
sampler. Setting `.format` or `.sampler` changes that. Document each field's zero-meaning in a
trailing comment.

**A state contract on every function.** One comment line, fixed format, stating what the
function touches:

```c
vkmin_mat4 vkmin_mat4_mul(vkmin_mat4 a, vkmin_mat4 b);    // pure
uint64_t   vkmin_address(vkmin_ctx*, vkmin_buffer);        // reads ctx
vkmin_image vkmin_make_image(vkmin_ctx*, const vkmin_image_desc*); // writes ctx, gpu
```

Carmack's action item in the functional programming essay was to survey every function for the
external state it can reach and write that down in a comment. This is that, made mandatory and
grep-able. It is the closest C11 gets to the `functional` keyword he wished for. A function whose
contract says `pure` and is not will fail review.

**One prefix, `verb_noun`, no cleverness.** `vkmin_make_*`, `vkmin_free_*`, `vkmin_frame_begin`,
`vkmin_frame_end`, `vkmin_draw`, `vkmin_save_png`. No `_Generic`, no macro-generated names, no
function that dispatches on a type tag. If a name cannot be guessed, it is wrong.

**No callbacks, ever.** The library never calls user code. Failure aborts through `VKMIN_FAIL`,
which is a macro the integrator can redefine before including the header, in the `stb` style.
That is compile-time configuration, not a runtime hook, and it carries no state.

**Compile-time configuration only.** `VKMIN_MAX_IMAGES`, `VKMIN_MAX_BUFFERS`, `VKMIN_ASSERT`,
`VKMIN_FAIL`, `VKMIN_NO_PLATFORM`. All have defaults. All are documented at the top of the
header in one block.

**Single-threaded, and it says so.** One line in the header: all calls on one thread, in order,
no exceptions. Carmack's stated preference for a simple polled loop over threads in reliability-
critical code applies here in full. Multi-threaded recording is a parallel implementation for
someone else's version.

## The journal

This is the feature that makes v0.3 different from every other thin GPU layer, and it is the
1998 `.plan` insight applied at the API boundary.

Every `vkmin_*` call takes a context and plain-data arguments. Therefore every call can be
recorded — function id, then the argument structs, byte for byte — to an append-only file, and
replayed later by reading the file and issuing the same calls. Because the render path reads no
clock and no randomness, replay produces identical frames.

`+journal record trace.vkm` writes one. `vkmin_replay(ctx, "trace.vkm")` plays it back, and
`./cube --replay trace.vkm --frame 60 --out shot.png` does so headless from the command line.
Resource creation is recorded with its data, so a journal is self-contained.

What this buys: a bug report becomes a file. A visual regression becomes a journal plus a frame
number, bisectable by an agent with no human describing what they saw. And the golden-image
harness gains a second, stronger form — record the examples once, replay them forever, compare
pixels. A journal that replays differently on a new commit is a regression by definition.

Record at the one place all calls already pass through. Do not instrument each function
individually.

## Everything else

**Pure maths.** `vkmin_math.h`: vectors, matrices, quaternions, all by value, all `pure`,
nothing mutating in place. Carmack's own example was an `idVec3` that had `Normalize()` for a
decade and never `Normalized() const`. Here there is only the latter.

**Examples are tests.** `examples/01_clear.c` through `06_cube.c`, each under a hundred lines,
each buildable alone against the header, each producing a golden image in `make test`. The
examples are the tutorial, and if one stops compiling the build fails. Number seven is the
journal replay of number six.

**Shader hot reload.** `+hotreload 1` makes `vkmin_frame_begin` check the SPIR-V files' mtimes
at one fixed point and rebuild affected pipelines. It is a single unconditional check that
usually does nothing — the execute-then-inhibit shape — not a watcher thread. Iteration speed is
the thing Carmack has been most consistent about valuing, and this is the cheapest form of it.

**Introspection as text.** `vkmin_stats(ctx)` returns a plain struct: GPU milliseconds per
pass, draw count, resource counts, memory in use. `vkmin_dump(ctx, FILE*)` prints the entire
context state — every live resource, its name, its size, its generation — as plain text. Both
humans and models read text; Carmack's remark that anything which is not readable text files
keeps stepping on landmines is the design rule here.

**`vkmin_probe`.** A pure function that inspects the device and returns a report struct without
creating anything: which path would be chosen, which features are present, why. Lets a user or
an agent answer "will this run here" before it fails.

**Amalgamation.** `make amalgamate` generates a single `vkmin_single.h` with an
`VKMIN_IMPLEMENTATION` block from the two-file source of truth. Generated, never hand-edited,
checked in CI to compile standalone. The two-file layout stays canonical.

## What the cube looks like afterwards

This is the acceptance test for the API's shape, and it should be `examples/06_cube.c` nearly
verbatim. If it needs more than this, the API has too much surface.

```c
#include "vkmin.h"
#include "shared.h"
#include "cube_data.h"

int main(int argc, char** argv) {
    vkmin_ctx* ctx = vkmin_init(&(vkmin_desc){ .argc = argc, .argv = argv, .title = "cube" });

    vkmin_buffer   vb   = vkmin_make_buffer(ctx, &(vkmin_buffer_desc){ .data = cube_verts, .size = sizeof cube_verts });
    vkmin_image    tex  = vkmin_load_png(ctx, "assets/grid.png");
    vkmin_pipeline pipe = vkmin_make_pipeline(ctx, &(vkmin_pipeline_desc){
        .vs = cube_vert_spv, .vs_size = sizeof cube_vert_spv,
        .fs = cube_frag_spv, .fs_size = sizeof cube_frag_spv,
        .depth = true, .cull = VKMIN_CULL_BACK });

    while (vkmin_frame_begin(ctx, &(vkmin_clear){ .r = 0.1f, .g = 0.1f, .b = 0.12f })) {
        vkmin_mat4 mvp = cube_mvp(vkmin_frame_index(ctx), vkmin_aspect(ctx));  // pure
        vkmin_draw(ctx, pipe, &(cube_push){ .mvp = mvp, .vertices = vkmin_address(ctx, vb),
                                            .texture = vkmin_index(ctx, tex) },
                   sizeof(cube_push), 36, 1);
        vkmin_frame_end(ctx);
    }
    vkmin_shutdown(ctx);
}
```

`vkmin_frame_begin` returning false is how the loop ends: window closed, `--exit-after` reached,
or `--frame N` rendered. Command-line handling lives inside `vkmin_init` because every program
wants the same flags and nobody wants to write the parser.

## Milestones

Each leaves every existing golden image identical.

1. **Header rewrite.** Typed handles, zero-default descs, state contracts, compile-time config
   block, the threading statement. No behaviour change.
2. **Resources are numbers.** Bindless image array and buffer device addresses on both paths.
   `vkmin_bind` deleted. `vkmin_draw` takes the push block. `shared.h` gains the push structs.
3. **The journal.** Record and replay. Test: record `06_cube`, replay it headless, goldens
   identical.
4. **Examples as tests**, 01 through 07.
5. **Maths header, hot reload, `vkmin_stats`, `vkmin_dump`, `vkmin_probe`.**
6. **Amalgamation** and its CI check.

## Acceptance

`vkmin.h` under 300 lines; core under 2500 with both paths; every example under a hundred
lines; the cube example matching the sketch above in shape. Every public function carries a
state contract and a review confirms each `pure` is true. A recorded journal of every example
replays to identical pixels on both paths under lavapipe. `make test` passes from clean with no
GPU.

And the qualitative test, which is the one that matters: hand the header alone to someone who
has never seen the project and time them to a textured cube. Report the number. If it is over an
hour, the header is not finished.

Report what was run and what was believed.
