# v0.6 proposal: vkmin and sndmin as one usable C11 toolkit

Implementation follow-up: [v0.6 integration candidate](v0.6-integration.md).
That document supersedes the initial timing/defaults/parser findings below
where fixes and tests are described, and records the remaining release gates.

5 September 2026. This is an initial source review and a release plan, not a
claim that v0.6 is implemented or that the public APIs are frozen.

The next release should consolidate what exists. Two small contexts, typed
numeric resource handles, explicit frame input and one borrowed journal stream
are a sound starting point. Keep the simulation in game code. Let it supply
camera and listener values to the two libraries; neither library should drive
the other or reach into the other's context. An opaque context owns mutable
resources and queues; passing it explicitly does not make an operation pure.

## Findings and decisions to make

| Priority | Current evidence | Proposed v0.6 outcome |
|---|---|---|
| Release gate | Latest `sndmin-verification.md` reports 107 graphics checks with 14 failures: six Corridor comparisons and eight current/frozen valley comparisons. Earlier reports used different working-tree snapshots. | Reconcile the concurrent changes into one revision, reproduce the failures there, explain every image delta and repair replay before deliberately approving any new baseline. Do not call the release green from one subsystem's result. |
| High | `sndmin_frame` maps index N to sample 800*N. The valley calls it from its rendering loop. The existing shared test captures frames 0 and 3. | One 60 Hz simulation timeline owns input, camera, listener and music events. Advance audio on every simulation tick; render at chosen checkpoints. Compare dense and sparse rendering schedules over a complete score. Define pause, restart, late commands and end-of-stream draining. Keep the live device's scheduling offset separate from simulation time. |
| High | `sndmin_play` defaults zero gain to unity; `sndmin_set` uses zero to mute; frame bus gains use zero for unity and negative to mute. | Choose a consistent way to express defaults versus explicit zero before freezing the API. A documented default descriptor plus literal setter values is a candidate. Test mute, fade, restore and replay through the same public example. |
| High | vkmin documents fatal errors. sndmin resource creation returns zero handles; queue/render failures also appear in results and counters. | Distinguish programmer contract violations from recoverable device/file/capacity failures. Put the policy and borrowed/copied/retained lifetime on each operation. A caller must be able to tell whether a play request was accepted. Do not add a general callback framework just for errors. |
| High | `sndmin_load_song` creates context patches while parsing and only frees the temporary song on parse failure. | Make failed loads transactional: repeated malformed songs must not consume resource capacity or leave journalled partial resources. Add a failure/retry test against the real parser. This finding is from inspection, not a reproduced test here. |
| Medium | `sndmin.h` includes `vkmin_math.h`; `demo/valley_audio.h` includes the private DSP header for its deterministic wind sine. | Keep the public-only music example as an API check. Remove the game adapter's private-header dependency. Decide whether a tiny shared numeric header earns its maintenance cost; avoid an umbrella engine context. Verify each public header standalone, in both include orders, and in separate C11 translation units. |
| Medium | Graphics handles have generations and explicit destruction. Audio resources are immutable after the first frame and live until shutdown; streams have one consumer. | Write an ownership table, including stale/cross-context handles and voice stealing. Decide whether scene transitions actually require individual audio resource unloading. Add it only with a bounded lifetime protocol that joins or acknowledges the mixer. |
| Medium | Shared journal packet framing is little-endian, but version-1 payloads use native C layouts. Tag extraction ignores the outer frame field. Input demos, GPU command journals and audio command journals have different replay requirements. | Publish those distinct guarantees. Validate packet/frame ordering and add metadata for payload version, tick/sample rate and build/asset identity where needed. Reject incompatible replay clearly. Do not promise arbitrary ABI or driver bit equality. |
| Medium | The score can be expressed entirely through patch/play/frame calls. Tracker presets have short, fixed pad gates and songs expand their notes when played. | Keep musical arrangement in demo code for now. Add tracker ties or timed event scheduling only when a second real example needs them. Exercise queue limits with long scores; avoid silently scheduling an unbounded song. |

Typed integer handles help C reject accidental resource-type mixing. They are
not interchangeable with a texture slot, a scene object ID or a GPU address.
These numbers remove pointer lifetime exposure at the boundary; ownership,
generation and context checks still do the correctness work. Small headers alone
do not prove ease of use: defaults and failure paths must also be unsurprising.

## Acceptance sequence

1. Consolidate and name the revision under review. Run the complete graphics and
   audio harness, mandatory analysis and shader validation. Preserve old journals
   and reference paths while investigating divergences.
2. Add one public-header-only A/V example: sample input once, update a plain game
   state, pass one tick's values to both contexts, play/stop/mute a sound, draw,
   and shut down with the borrowed journal closed last. Build it without private
   headers or a Vulkan SDK when only its audio part is selected.
3. Capture at least the 120-second valley route with music, then reproduce exact
   WAV bytes and selected PNGs from the same journal under both Vulkan paths.
   Include a visible action with a known audio onset sample. Repeat with rendering
   skipped but simulation ticks retained; verify the same PCM. Test pause/restart
   and a rejected malformed or incompatible journal.
4. Run Linux, Windows and macOS builds and report actual results separately.
   Verify live A/V latency, a ten-minute run and device teardown on real hardware;
   offline equality cannot establish those properties. Cross-machine floating
   point equality is a test result to obtain, not an assumed promise.
5. Give a working C game developer the two headers and that example. Ask them to
   add a moving sound, a mute button and a scene restart. Record stumbling points
   and missing operations. Developer appeal remains a hypothesis until this test.

## First practical probe: Morning water

`demo/valley_score.h` is an original two-minute ambient composition using only
the public sndmin API: a slowly filtered pad, a triangle bass and sparse high
triangle notes. Eight 15-second phrases move through D minor, F, C, G suspended,
B-flat, F, A minor and D suspended. There are no sampled instruments or drums.
The final phrase releases early; the standalone WAV includes four extra seconds
for the effects tail. It is finite, not a seamless loop.

`examples/sndmin/05_ambience.c` creates three patches before frame zero, advances
7,440 integer ticks, and writes WAV, spectrogram and journal. The optional
graphical `sndmin-valley` adapter now uses the same score at half gain beneath
its wind, river and birds. The original rhythmic tracker example is retained.
No new core audio feature was necessary.

The score helper requires every simulation tick. Isolated graphics captures
with skipped ticks are not a complete musical performance; reconstructing that
history belongs to the timeline work above. Shared command replay can reproduce
what was captured but cannot invent game events the application never issued.

Build and render from the repository root:

```
make -f Makefile.sndmin sndmin
build/sndmin/05_ambience tests/out/sndmin/05_ambience
make -f Makefile.sndmin sndmin-test
make HEADLESS=1 sndmin-valley
```

The score test compares direct output with current and frozen journal replay
and a compact SHA256 WAV golden, checks the exact 48 kHz stereo sample count,
headroom, audible energy in every phrase and the release tail. The checked-in
compressed journal allows old commands to be replayed without keeping another
24 MB WAV in Git. Listening quality still requires listening.

## Verification of this change

Run here on Windows x64 with w64devkit GCC 16.2.0:

- `make -f Makefile.sndmin -j4 sndmin-test` passed, including GCC analysis,
  cppcheck, callback guards, the four existing audio goldens and the new score.
- Direct, current-journal and frozen-journal score WAVs are byte-identical:
  SHA256 `6de3121c3669a48e3ffccf5a19d75ee9411fb0237b43dbadc89dd1967f65c5c8`.
  Output is 5,952,000 stereo frames at 48 kHz (124 seconds), peak 0.07474 of
  full scale, final-second RMS 0.0000812. No stolen voices, late commands,
  engine underruns or dropped commands; no active voices remain at completion.
- `make -j4 HEADLESS=1 sndmin-valley` passed. The shared-journal smoke test
  reproduced two PNGs, WAV and spectrogram exactly from modern capture to
  legacy replay under lavapipe. This is the short test, not the proposed
  full-route/sparse-render acceptance test.

The complete graphics harness was not rerun for this music change. Its earlier
failures remain release work, not newly approved images. Live listening,
full-route A/V timing and developer usability have not been evaluated here.
The suite log is `tests/out/sndmin/ambience-suite.log`; the score WAV and
spectrogram are `tests/out/sndmin/05_ambience.wav` and `.png`.
